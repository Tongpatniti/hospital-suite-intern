# ระบบแจ้งซ่อม (repair-app)

สร้างจากแม่แบบ `example-app` ตาม design spec v1.3 (Phase 1 + SLA + audit log)

## ติดตั้งและรัน

```bash
pnpm install                          # ที่ root ของโปรเจกต์ (ลิงก์ workspace ให้แอปใหม่)
pnpm --filter backend db:setup        # ถ้ายังไม่เคยรัน
pnpm --filter backend db:setup:repair # สร้างตาราง repair_* + permission + ครุภัณฑ์ตัวอย่าง
pnpm backend                          # API ที่ http://localhost:3002
pnpm --filter repair-app dev          # http://localhost:5181/repair/
```

การเชื่อมต่อฐานข้อมูลอ่านจาก `apps/backend/.env` (`DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`)

บัญชีทดสอบ: `admin / admin123`, `staff / staff123`, `tech / tech123`, `supply / supply123`

## ใครทำขั้นไหน

| ขั้น | ผู้ทำ | กรอกเพิ่ม |
|---|---|---|
| รับงาน → เริ่มดำเนินงาน | ช่าง | – (ยืนยัน/ยกเลิก) |
| สั่งซื้ออะไหล่ | ช่าง | ฟอร์มรายการอะไหล่ + รูป (ไม่บังคับ) |
| รับเรื่อง → อนุมัติ/จัดซื้อ → อะไหล่ถึงคลัง | พัสดุ | ราคาจริงในตารางอะไหล่ |
| ส่งเรื่องซ่อมภายนอก | ช่าง | เหตุผล, ร้านที่เสนอ, ประกัน + รูป (ไม่บังคับ) |
| รับเรื่อง → ส่งร้าน → รับเครื่องคืน | พัสดุ | ร้าน, วันที่ส่ง / วันที่รับคืน, ค่าซ่อม, เลขใบแจ้งหนี้ |
| ตรวจรับเครื่องแล้ว ซ่อมต่อ / รับอะไหล่แล้ว ซ่อมต่อ | ช่าง | – |
| ซ่อมเสร็จ | ช่าง | รายละเอียด + ผลการซ่อม + รูป (ไม่บังคับ) |
| ตรวจรับและปิดงาน | ผู้แจ้ง | ดาว 1–5 + ความเห็น |
| ส่งกลับซ่อม | ช่าง ("ส่งกลับซ่อมอีกครั้ง") / ผู้แจ้ง ("ไม่ผ่าน ส่งกลับซ่อม") | เหตุผล |

## หน้าจอ

| เส้นทาง | หน้าที่ |
|---|---|
| `/repairs` | รายการงานซ่อม + สถานะ SLA |
| `/repairs/new` | แจ้งซ่อม + เตือนเมื่อเครื่องมีใบค้าง |
| `/repairs/:id` | Timeline, เปลี่ยนสถานะ, ผู้ติดตาม, สถานะในทะเบียนครุภัณฑ์ |
| `/assets/:id` | ประวัติการซ่อมรายเครื่อง |
| `/audit` | ประวัติการตั้งค่า (สิทธิ์ `repair.audit.view`) |
| `/settings` | ค่าตั้งระบบและ SLA (แก้ได้เมื่อมี `repair.settings`) |

## Backend

- `apps/backend/sql/repair.sql` — schema
- `apps/backend/src/modules/repair.ts` — API
- `apps/backend/src/modules/repair_sla.ts` — ตรวจงานค้างทุก `sla_scan_interval_min` นาที (สั่งรันทันที: `POST /api/repair-sla/run`)
- `apps/backend/src/modules/repair_common.ts` — สิทธิ์, transition, transaction + audit context

## ไฟล์แนบ

- รับรูป JPG, PNG, WEBP, HEIC และ PDF ขนาดสูงสุดตั้งได้ในหน้าตั้งค่า (ค่าเริ่มต้น รูป 15 MB, PDF 10 MB, 30 ไฟล์ต่อใบ)
- หน้าเว็บย่อรูปก่อนส่ง (ด้านยาวไม่เกิน 1920 px, แปลงเป็น WebP ซึ่งลบ EXIF/GPS) ไม่เก็บไฟล์ต้นฉบับ
- backend ตรวจชนิดจากเนื้อไฟล์, ขนาด, จำนวน, ไฟล์ซ้ำ และไม่รับ PDF ที่เข้ารหัสหรือมีสคริปต์
- ไฟล์เก็บที่ `apps/backend/uploads/repair/ปี/เดือน/` (เปลี่ยนได้ด้วย `UPLOAD_DIR` ใน `.env`)
- ขั้น "ซ่อมเสร็จ" บังคับแนบรูปอย่างน้อย 1 รูป
- HEIC เปิดได้เฉพาะเบราว์เซอร์ที่รองรับ (เช่น Safari) ที่อื่นจะแจ้งให้แปลงเป็น JPG ก่อน

## ยังไม่ทำในรอบนี้

- อะไหล่ / ซ่อมภายนอก / ใบเสนอราคา / ขั้นอนุมัติ (Phase 2)
- API ยังเชื่อ header `x-person-id` จากหน้าเว็บ เหมือนแอปอื่นในโปรเจกต์ฝึกงาน ต้องเปลี่ยนเป็นตรวจ token ก่อนขึ้นระบบจริง
